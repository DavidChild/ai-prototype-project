# 项目迭代版本

首页每个项目仅展示一张卡片。左下角选择迭代版本，点击卡片或“进入”打开所选版本；“新建版本”必须选择一个已有来源并填写项目内唯一的版本号。

MySQL 中的新建项目默认从 v1.0 开始。工作台 URL、页面 ID、生成内容和历史记录都保存在当前项目迭代的数据空间中。

存储中每个迭代拥有独立的 Project.id（工作台数据空间），同一逻辑项目以 familyId 关联。iteration 是显示的版本号，basedOnId 记录复制来源。沿用 /project/:id 路由，避免旧链接失效。项目名称和隐藏状态作用于整组迭代；删除项目将删除整组迭代，弹窗会明确告知。

复制在一个数据库事务中读取并写入项目、页面、页面生成历史、源文档和图片资产。所有数据库主键重新生成，版本引用、页面归属、文档归属同步重映射。PageSpec.id 保留为迭代内部的树节点标识，使菜单关系和已生成内容保持一致；不同迭代的数据库 Page.id 相互独立。复制中断时全部回滚，同一项目不能并发创建同名版本。

版本复制包含所有已保存的内容，不复制内存中的流式输出或微调对话。排队或生成中的来源需先停止或完成生成。

验证：`npm run test:project-iterations` 覆盖完整复制、独立编辑、从任意迭代派生、重复版本与并发拦截、失败回滚及整项目操作。`npm run test:storage` 会自动创建独立的临时 MySQL 测试库，完成后删除，不访问 `db_proto` 中的用户数据。
